# MapOS VPS v19 — 2026-09-01

V19 turns the existing map application into a guest-first, versioned platform release while keeping
the keyless core and the v18 rollback path.

## Highlights

- A shared four-mode shell, restored browser state and independent map, panel, modal and footer
  surfaces.
- A persistent keyboard- and pointer-resizable desktop panel, live canonical layer count, accessible
  basemap label, horizontally navigable presets, manifest-driven basemap groups and expandable
  multi-layer legends that remain clear of simultaneous drawers and the shared timeline.
- Versioned layer/feature/plan contracts, source-aware basemaps, saved places, richer Discover,
  planning with adjacent route segments, weather/events contributions and source-separated POI
  detail.
- A complete offline/manual planning path with editable names and stops, server save/reload,
  GPX/GeoJSON export and explicit provider mappings or visible fallback warnings for date, vehicle
  and route preferences.
- Safe AI proposals that require validated preview/confirmation rather than direct mutation.
- Guest-first linked identities with strict SIWE challenge binding and optional, explicitly configured
  ENS display metadata.
- Provider-neutral commerce and entitlement contracts with real payment processing disabled until a
  configured provider and verified webhooks exist.
- Public layer validator/import preview/commit/rollback foundations, including owner-bound durable
  previews that can cross API instances, and deterministic examples.
- A UI-neutral map runtime plus an offline clean-room starter that registers two checked-in layers,
  remains usable without WebGL and imports no MapOS product UI.
- A common game host, controller contract and neutral 3D fallback. Large historical GLBs stay out of
  the data-efficient v19 payload; the procedural character remains immediately usable.
- Distributed anonymous rate limits, SSRF/response guards, circuit breakers, privacy-safe operational
  metrics, real backup restore drill and per-surface failure containment.
- A complete authenticated account archive and transactional deletion path, with an explicit,
  pseudonymized commerce-audit retention response where financial records cannot be erased.
- Source-rights and attribution metadata remains visible advisory provenance in this
  operator-approved prototype. The optional `npm run audit:source-rights` is outside default tests,
  CI and deployment and cannot hide layers or restrict cache, export or AI paths. Provider access
  remains controlled by credentials, enablement, health, quotas and response safety.

## Compatibility and rollback

New migrations 0002–0009 are additive. Version 0001 adopts the checksum of the already-applied v18
bootstrap; it retains three historical constraint/type reconciliation statements, and the restore
drill proves they are no-ops on the exact v18 schema before running the candidate. The v1
compatibility adapter remains because legacy removal is telemetry-gated. The deployment retains
v18 as the immediate rollback release. See the
[upgrade guide](../upgrade-guides/v18-to-v19.md) and [compatibility policy](../compatibility-policy.md).
The narrower `VITE_MAP_RUNTIME_V2=0` build-time rollback restores direct layer handles without
changing manifests, stored data or MapOS UI.

## Known external gates

No release claim is made for a live payment provider, public package registry publication,
EIP-1271 contract-wallet verification, or a current official Base inventory indexer. Their
interfaces and safe disabled states are present; enabling them requires credentials and
provider-specific acceptance evidence.

The one-VPS deployment path requires a verified restore drill and automatic rollback checks before
cutover; the exact live run is recorded separately after rollout. It is not described as a
percentage cohort. Sticky blue/green traffic splitting remains the explicit infrastructure gate in
[ADR 0011](../adr/0011-single-node-rollout-and-cohort-gate.md).
